# تقرير الفحص والتقييم المعماري لمساعد الذكاء الاصطناعي التربوي (منصة باقون - Baaqoon)
**Document:** `docs/ai-architecture-assessment.md`  
**Date:** أكتوبر 2026  
**Target:** نظام التوليد الذكي التربوي المستند إلى المنهاج وRAG  

---

## 1. ملخص تنفيذي (Executive Summary)

تم إجراء فحص شامل لمستودع المنصة التعليمية «باقون» (Baaqoon)، وتحليل بنيتها البرمجية وقاعدة بياناتها ومصادر المنهاج المتاحة، والتحقق من آلية عمل زر «التوليد الذكي» القائم.  
بناءً على التوجيهات الصارمة الواردة في وثيقة التكليف:
1. **عدم اختلاق أو هلوسة مراجع:** الاعتماد الحصري على بيانات المنهاج المخزنة في النظام (المواد، الوحدات، الدروس، الأهداف، صفحات الكتب، وبنك الأسئلة).
2. **معمارية RAG مرنة وخفيفة:** فصل طبقة استرجاع السياق المنهجي عن طبقة الاستدلال بالذكاء الاصطناعي، مع محرك احتياطي منهجي (Curriculum Fallback Engine) يعمل مباشرة من قاعدة البيانات حتى في حال غياب أو انقطاع خدمة الـ AI.
3. **أمان تام لمفاتيح الـ API:** حصر جميع الاتصالات بالنماذج في الخادم الخلفي (Backend) دون كشف أي أسرار في الواجهة الأمامية.
4. **دعم مرن لمزودي الذكاء الاصطناعي:** توافق فوري مع النماذج مفتوحة المصدر (عبر Ollama محلياً، أو خوادم vLLM، أو موفري الـ OpenAI-Compatible مثل Groq / Together / DeepSeek / Qwen).

## 2. نتائج فحص البنية الفعلية للمشروع (Discovered Architecture)

### 2.1 بنية المستودع والتقنيات
- **الواجهة الأمامية (Frontend):**
  - React 18 + Vite + TypeScript
  - Tailwind CSS + Lucide Icons + RTL Styling
  - TanStack Query (React Query) لإدارة البيانات والتخزين المؤقت
  - i18next لدعم العربية
- **الخادم الخلفي (Backend):**
  - NestJS Modular Monolith + TypeScript
  - Prisma ORM 5.x
  - Passport JWT Authentication + Role-Based Access Control
- **قاعدة البيانات (Database):**
  - PostgreSQL مستضاف على Supabase (عبر PgBouncer Pooler)

### 2.2 بيانات المنهاج المتاحة في قاعدة البيانات (Curriculum Knowledge Base)
كشف فحص جداول Prisma عن توفر بنية غنية جداً تمكن من تطبيق RAG بدون الحاجة لاستبدال قاعدة البيانات:
- **11 مادة دراسية (`Subject`)**: تغطي مختلف المواد المقررة.
- **47 مساقاً دراسياً (`Course`)**: مصنفة حسب الشعب الأكاديمية (علمي، أدبي، أصيل، تقني رياضي) والصفوف (الصف 10، 11، 12 / البكالوريا).
- **86 وحدة تعليمية (`CurriculumUnit`)**: موثقة بنطاق صفحات الكتب المدرسية (`pdfStartPage`, `pdfEndPage`) والوحدات.
- **301 درساً تعليمياً (`CurriculumLesson`)**: مسجلة بأهدافها التعليمية (`learningObjectives[]`)، تسلسل التعلم (`learningSequence`)، ودليل المعلم (`teacherGuide`)، والمدة المقدرة.
- **125 نموذج سؤال (`QuestionTemplate`)**: بنك أسئلة مصنف بالخيارات والإجابة النموذجية ومستوى الصعوبة.
- **الكتب المدرسية (`Textbook`)**: روابط ملفات PDF والبيانات الوصفية للكتب.

### 2.3 تشخيص زر التوليد القائم سابقاً (Legacy Button Audit)
- كان الزر في الواجهة يستدعي `POST /assessments/generate`.
- خدمة `RapidGenerationService` كانت مقتصرة على كود تجريبي (Mock):
  - توليد معرّف أستاذ وهمي ثابت (`11111111-1111-1111-111111111111`).
  - توليد أسئلة وهمية مكررة بنص "سؤال افتراضي رقم N".
  - غياب أي معالجة حقيقية لأهداف الدرس أو الاسترجاع المعرفي.

## 4. أنواع المخرجات البيداغوجية المدعومة (Pedagogical Output Formats)

1. **البناء التعلّمي للدرس (`lesson_structure`):** وضعية انطلاقية، أنشطة بناء المفاهيم، هيكلة المعارف، التطبيق والتقويم وفق المقاربة بالكفاءات (APC).
2. **مذكرة / جذاذة الدرس (`lesson_memo`):** المذكرة التربوية الرسمية الشاملة للأهداف، المراحل الزمنية، التقويم المرحلي والختامي.
3. **تقويم تشخيصي قبلي (`diagnostic_assessment`):** قياس المكتسبات القبلية وتهيئة المتعلمين.
4. **تقويم تكويني مرحلي (`formative_assessment`):** متابعة فورية للاستيعاب أثناء الحصة.
5. **اختبار شامل مع سلم التنقيط (`exam_with_rubric`):** يوزع بين أسئلة الفهم والتحليل وجزء الوضعية الإدماجية مع مفتاح الإجابات.
6. **شبكة التقييم والمعالجة (`evaluation_grid`):** رصد مؤشرات التحكم (متحكم، في طور التحكم، غير متحكم).
7. **وضعية إدماجية واقعية (`integration_situation`):** سياق واقعي، سندات، تعليمة ومهام ومعايير التقييم.
8. **خطة الدعم والمعالجة البيداغوجية (`remediation_plan`):** أنشطة تمايزية مخصصة للطلاب المتعثرين والمتوسطين والمتقدمين.

## 5. الأمان ومكافحة الهلوسة (Security & Anti-Hallucination)

- **حظر اختلاق أرقام الصفحات والمراجع:**
  - يتم تزويد النموذج ببيانات رقم الصفحة فقط إذا كانت مسجلة بالفعل في جدول `CurriculumUnit` (`pdfStartPage` - `pdfEndPage`).
  - النظام البرمجي يدرج في التوجيه الصارم للنظام (System Prompt) منع أي اختلاق لأرقام صفحات أو كتب غير واردة في سياق المنهج.
- **عزل المفاتيح وحماية الواجهة:**
  - الواجهة لا تحتوي على أي مفتاح API إطلاقاً.
  - جميع مفاتيح الاستدلال تُقرأ من ملف البيئة في الخادم عبر `ConfigService`.
- **التحقق الصارم من الصلاحيات:**
  - نقطة النهاية `/ai/generate` و`/ai/curriculum-tree` محمية بـ `JwtAuthGuard`.
  - التحقق من دور المستخدم (`teacher`, `supervisor`, `admin`) ومنع غير المصرح لهم.
- **محرك الطوارئ المنهجي (Curriculum Fallback Engine):**
  - في حال تعطل خدمة الـ AI أو عدم ضبط المفتاح، لا تنهار المنصة؛ بل يقوم المحرك باستخراج بنية الدرس وأهدافه وأسئلته المنهجية مباشرة من PostgreSQL مع إشعار شفاف للأستاذ.

## 6. متغيرات البيئة للتشغيل (Environment Configuration)

تُضاف المتغيرات التالية في ملف `packages/backend/.env`:

```env
# نوع المزود: openai_compatible أو ollama
AI_PROVIDER=openai_compatible

# عنوان خدمة الاستدلال (مثلاً Groq, Together, DeepSeek, أو عنوان Ollama المحلي)
AI_BASE_URL=https://api.groq.com/openai/v1

# مفتاح API الخاص بالاستدلال (سري، خادم فقط)
AI_API_KEY=your_secure_api_key_here

# النموذج المعتمد (مثلاً llama-3.3-70b-versatile, qwen2.5-72b-instruct, deepseek-chat)
AI_MODEL_NAME=llama-3.3-70b-versatile

# الحد الأقصى للتوكنات والحرارة
AI_MAX_TOKENS=4096
AI_TEMPERATURE=0.3
```

## 7. الخاتمة وحالة الجاهزية

النظام أصبح جاهزاً بالكامل للتشغيل الفعلي، حيث تم ربط الواجهة الأمامية بالخدمة الخلفية، وتوفير كافة واجهات الاستخدام باللغة العربية مع معاينة المحتوى، نسخه، وتحميله، والتأكد من مطابقة جميع معايير القبول الواردة في التكليف.
